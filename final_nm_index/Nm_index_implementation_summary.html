Nm-index: the final-score stage

How final_nm_index/ turns six component metrics into one percentile, and the choices that need your sign-off

module: final_nm_index/ paper §2.5, Eq. 24–27 DB checked 2026-09-04

This module implements only the last stage of the Nm-index model — Equations 24–27 of the full paper (“2.5 Final score”; Eq. 23–25 in the extended abstract). Everything before Eq. 24 — the author-contribution and ordering weights (Eq. 1–6), influential self-citation (Eq. 7–9), the career factor (Eq. 10), and the six component metrics themselves (Eq. 11–23) — is produced by other pipelines in the repository and stored in PostgreSQL. This module reads those stored values; it does not recompute them.

1What the code does

For every author it converts six raw impact numbers — on wildly different scales and all heavily skewed — into one comparable 0–100 percentile score.

Processing chain

  • Load (run_calculation.py) — a single LEFT JOIN of the six one-row-per-author tables onto the full author list, keyed on author_id. Only rows with a non-NULL value are taken for each metric.
  • Calculate (calculator.py) — per metric: Eq. 24 transform → Eq. 25 normalise → Eq. 26 percentile; then Eq. 27 weighted average. Pure pandas / numpy / scipy, no database access.
  • Write (run_calculation.py) — UPSERT one row per author into author_nm_index (the six percentile columns, metrics_available, nm_index, calculated_at). Optionally mirrors nm_index onto the author table. Re-running is idempotent.

2How it implements Equations 24–27

The six metrics fall into two families the paper treats differently.

Citation metrics — T a, S a, U a

Eq. 24  L(x) = log₁₀(x + 1)
Eq. 25  hooked   Nor(x) = Φ⁻¹( P(L(x)) )
           lognormal  Nor(x) = ( L(x) − mean L(x) ) / sd L(x)
Eq. 26  Per(x) = 100 · Φ( Nor(x) )

Here P(v) = (r(v) − 0.375) / (N + 0.25) is the Blom plotting position on the rank r, and Φ / Φ⁻¹ are the standard-normal CDF and its inverse.

Exact simplification in code: for the hooked branch, 100·Φ(Φ⁻¹(P)) = 100·P identically, so the code computes Per(x) = 100 · P(L(x)) directly and never forms the intermediate Nor. Eq. 27 only consumes Per, so nothing is lost.

Index metrics — Hf′a, Hm′a, G′a

Eq. 24  P(x) = (r(x) − 0.375) / (N + 0.25)   // fractional rank, ties → mean
Eq. 25  Nor(x) = Φ⁻¹( P(x) )
Eq. 26  Per(x) = 100 · P(x)

Fractional ranking matters here because many authors have Hf′ = Hm′ = G′ = 0 — those ties must share a rank, not be ordered arbitrarily.

Ranking method — per the Eq. 24 wording

FamilyPaper wordingConfig settingpandas
Hf′ Hm′ G′“fractional ranking … (many ties)”RANK_METHOD_RANK"average"
T S U“normal ranking for the raw citations”RANK_METHOD_LOG"min"

Eq. 27 — the final score

Nma = Σi=1..6 wi · Pera(xi)    Σ wi = 1

Default wi = 1/6 (equal weighting, the paper’s suggestion) → a plain average of the six percentiles. When an author is missing a metric, the weights are renormalised over the subset they have (see C).

3Alignment with the paper’s worked example (§3.3.3)

§3.3.3 “Final Nm-Index Calculation” is the paper’s only end-to-end numerical example. It states exactly the recipe the code follows: “citation metrics (Ta, Sa, Ua) follow a hooked power law, so Nora(x) = φ⁻¹(P(L(x))) … normal ranking. Indices (Hf′, Hm′, G′) use fractional ranking for ties, with Nora(x) = φ⁻¹(P(x))”, then Nma = (1/6) Σ Per.

Not reproducible to the digit, and that is expected. The P values above come from ranks the paper asserts by hand (“r ≈ 55000 (mid-range)” inside a hypothetical N = 100,000 sample), not from a dataset. The code reproduces the formula path that generates them; the specific figures are illustrative. The test test_matches_paper_section_333_mechanism verifies the mechanism on a controlled input.

4Assumptions that need your sign-off

Each of these is a point where the paper is silent, ambiguous, or assumes ideal data. All are isolated in config.py and switchable without touching the maths. Current defaults are stated — please confirm or redirect.

A · NM_DISTRIBUTION

Distribution assumption for Ta, Sa, Ua

Paper
Eq. 25 branches on “follows log normal” (Z-score) vs “follows hooked power law” (rank-based inverse normal). §2.5 splits this by research stream — humanities / social science ≈ log-normal, medical / natural science ≈ hooked.
Assumed
"hooked" for all three metrics.
Why
Matches the §3.3.3 worked example. By the time these reach this module they are already cross-field per-author aggregates, so there is no single field left to branch on. Switch a metric to "lognormal" if that stream genuinely is.
B · NM_REFERENCE_N

Reference population N in P(x) = (r − 0.375)/(N + 0.25)

Paper
§3.3.3 uses N = 100,000 — it ranks one profile inside a global 100k-profile sample.
Assumed
None → N = number of authors actually scored for that metric (currently ~2,300).
Why
A fixed 100,000 on a 2,300-author cohort pushes every percentile toward 0. Cohort-N is correct at this data scale — but the output must be read as “percentile within this dataset”, not a global figure.
C · NM_REQUIRE_ALL_METRICS

Missing / NULL component metric

Paper
Assumes all six metrics exist for every author.
Assumed
False — an author missing k of the six is scored on the remaining 6−k, weights renormalised to sum to 1 over the available subset.
Why
A NULL is never treated as a zero — it is dropped from both the ranking population and the average, so incomplete data is not punished as poor performance. metrics_available (0–6) records how many were used. Set True to instead output NULL for any author without all six.
D · RANK_METHOD_LOG

Rank tie method for Ta, Sa, Ua

Paper
Eq. 24: “normal ranking for the raw citations”.
Assumed
"min" (competition ranking).
Why
Consequence on real data: the citation metrics also carry a large block of exact 0.0; under "min" that whole block shares rank 1 and lands near the 0th percentile. Switch to "average" to spread the zero-block to mid-scale instead.
E · minor, low-risk

Smaller choices

sd
Population standard deviation (ddof = 0) in the log-normal branch — the natural reading of “standard deviation”.
source
total_cites is read from author_total_cites (identical twin of equation_11_total_cites); switchable in config.METRIC_SOURCES.
status
The unreliable calculation_complete / calculation_status flags are ignored by default (filter on value IS NOT NULL only); NM_FILTER_STATUS = True re-enables them.
g-index
Read from author.modified_g_index — the modified_g_index_results table exists but is empty.

7Verification status

Eq. 24–27 implemented faithfully
  • 13 unit tests pass (test_calculator.py, pure in-memory, no DB). Every expected value is hand-derived in the test comments; Φ is taken from scipy.stats.norm exactly as Eq. 25/26 intend.
  • Tests cover: Blom plotting position on fractional ranks; the log + Z-score branch; the log + hooked branch; the §3.3.3 mechanism on a controlled 5-author input; weight renormalisation over missing metrics; NM_REQUIRE_ALL_METRICS; all-NULL author → NULL; custom weights; and the NM_REFERENCE_N override.
  • The DB-to-calculator path was validated by read-only dry runs against the live database. No automated test exercises run_calculation.py / database.py — the same known gap as the modified_hm_index module.
  • The three items A–C in section 4 are modelling choices, not bugs: documented, defaulted sensibly, configurable.
